### О чем эта подглава
В этой части мы проведем аудит кодовой базы сервиса `TradePulse`, зафиксируем контрольный срез структуры каталогов и проверим работоспособность всех системных компонентов перед внедрением базы данных.

* **Что сделаем:** зафиксируем точное состояние файлов проекта по итогам первой главы, проверим конфигурационные файлы, обновим манифест `docker-compose.yml` для подготовки инфраструктуры СУБД и верифицируем окружение через `just`.
* **Исходное состояние проекта:** чистый инфраструктурный контур, созданный в главе 1 (uv, src-layout, structlog, ruff, mypy, just).
* **Ветка в репозитории:** `chapter-02-start` (стартовая точка для тех, кто начинает чтение со второй главы).

> **Что почитать для углубления:**
> * Тим Питерс, *«Программирование бэкенда на Python. Практическое руководство»* (БХВ, 2025) — проектирование компоновки проекта с выделенными слоями персистентности.
> * Методология *«The Twelve-Factor App»*: фактор II (Dependencies) и фактор IV (Backing services) — отношение к базам данных как к подключаемым ресурсам.

### Архитектурный срез: исходное дерево каталогов

Перед добавлением ORM-моделей, миграций и пулов подключений репозиторий `TradePulse` организован по схеме `src-layout`. Каждый каталог имеет строгую зону ответственности:

```text
tradepulse/
├── .env.example                # Шаблон переменных окружения
├── .dockerignore               # Исключения контекста сборки Docker
├── .gitignore                  # Исключения системы контроля версий Git
├── .python-version             # Фиксация рантайма Python 3.13
├── docker-compose.yml          # Манифест оркестрации контейнеров с профилями
├── Dockerfile                  # Многоэтапный сценарий сборки продакшен-образа
├── Justfile                    # Декларативный интерфейс команд проекта
├── pyproject.toml              # Центральный манифест проекта и dev-инструментов
├── README.md                   # Базовая документация
├── uv.lock                     # Зафиксированный граф зависимостей
├── src/
│   └── tradepulse/             # Основной исполняемый пакет
│       ├── __init__.py
│       ├── main.py             # Точка входа ASGI и lifespan-управление
│       ├── api/                # Транспортный уровень (эндпоинты и роутеры)
│       │   ├── __init__.py
│       │   └── v1/             # Версионированные контроллеры API
│       │       └── __init__.py
│       ├── core/               # Инфраструктурное ядро
│       │   ├── __init__.py
│       │   ├── config.py       # Pydantic-настройки и чтение переменных окружения
│       │   └── logger.py       # Конфигурация structlog (dev / test / prod)
│       ├── models/             # Слой ORM-моделей (будет наполнен во второй главе)
│       │   └── __init__.py
│       ├── repositories/       # Слой прямого доступа к данным (DAO / Repository)
│       │   └── __init__.py

│           └── __init__.py
└── tests/                      # Набор тестов и окружение pytest
    ├── __init__.py
    └── conftest.py             # Глобальные фикстуры
```

### Подготовка инфраструктуры: добавление PostgreSQL в Docker Compose

На этапе первой главы манифест `docker-compose.yml` обслуживал только контейнеры API и тестовую почтовую заглушку Mailpit. Для реализации слоя персистентности нам потребуется локальный экземпляр СУБД PostgreSQL.

В соответствии с концепцией двенадцатифакторных приложений (*The Twelve-Factor App*) база данных является подключаемым ресурсом (*Backing Service*). В контуре локальной разработки она должна подниматься рядом с сервисом, не требуя ручной установки СУБД на хостовую систему разработчика.

Откройте `docker-compose.yml` и добавьте сервис `postgres` в общий манифест:

```yaml
services:
  # ---------------------------------------------------------
  # 1. Реляционная база данных PostgreSQL 17
  # ---------------------------------------------------------
  postgres:
    image: postgres:17-alpine
    container_name: tradepulse-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-tradepulse}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-tradepulse_password}
      POSTGRES_DB: ${POSTGRES_DB:-tradepulse_db}
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - tradepulse-network
    # База данных требуется как в dev-режиме, так и при локальном боевом тестировании
    profiles:
      - dev
      - prod

  # ---------------------------------------------------------
  # 2. Боевой сервис API (профиль "prod")
  # ---------------------------------------------------------
  api:
    build:
      context: .
      dockerfile: Dockerfile
    image: tradepulse-api:latest
    container_name: tradepulse-api
    restart: unless-stopped
    depends_on:
      - postgres
    ports:
      - "8000:8000"
    environment:
      - PYTHONUNBUFFERED=1
      - ENVIRONMENT=production
      - DATABASE_URL=postgresql+asyncpg://${POSTGRES_USER:-tradepulse}:${POSTGRES_PASSWORD:-tradepulse_password}@postgres:5432/${POSTGRES_DB:-tradepulse_db}
    networks:
      - tradepulse-network
    profiles:       
      - prod         

  # ---------------------------------------------------------
  # 3. Сервис для активной разработки (профиль "dev")
  # ---------------------------------------------------------
  api-dev:
    build:
      context: .
      dockerfile: Dockerfile
    image: tradepulse-api:dev
    container_name: tradepulse-api-dev
    depends_on:
      - postgres
    command: >
      uvicorn tradepulse.main:app
      --app-dir src
      --host 0.0.0.0
      --port 8000
      --reload
    volumes:
      - ./src:/app/src:ro
    ports:
      - "8000:8000"
    environment:
      - PYTHONUNBUFFERED=1
      - ENVIRONMENT=development
      - DEBUG=True
      - DATABASE_URL=postgresql+asyncpg://${POSTGRES_USER:-tradepulse}:${POSTGRES_PASSWORD:-tradepulse_password}@postgres:5432/${POSTGRES_DB:-tradepulse_db}
    networks:
      - tradepulse-network
    profiles:
      - dev

  # ---------------------------------------------------------
  # 4. Вспомогательная утилита: почтовая заглушка Mailpit
  # ---------------------------------------------------------
  mailpit:
    image: axllent/mailpit:latest
    container_name: tradepulse-mailpit
    ports:
      - "8025:8025"
      - "1025:1025"
    networks:
      - tradepulse-network
    profiles:
      - dev
      - tools

volumes:
  postgres_data:
    driver: local

networks:
  tradepulse-network:
    driver: bridge
```

### Обновление конфигурации окружения (.env)

Добавьте в локальный файл `.env` параметры аутентификации и строку подключения к базе данных для хост-машины (обратите внимание на указание хоста `localhost`, когда приложение запускается вне Docker-контейнера через `uv run`):

```dotenv
COMPOSE_PROFILES=dev

# Параметры подключения к PostgreSQL
POSTGRES_USER=tradepulse
POSTGRES_PASSWORD=tradepulse_password
POSTGRES_DB=tradepulse_db
POSTGRES_PORT=5432

# URL для локального запуска из терминала через uv run
DATABASE_URL=postgresql+asyncpg://tradepulse:tradepulse_password@localhost:5432/tradepulse_db
```

Синхронизируйте файл `.env.example`, чтобы новые разработчики могли скопировать актуальный шаблон:

```dotenv
COMPOSE_PROFILES=dev

POSTGRES_USER=tradepulse
POSTGRES_PASSWORD=tradepulse_password
POSTGRES_DB=tradepulse_db
POSTGRES_PORT=5432

DATABASE_URL=postgresql+asyncpg://tradepulse:tradepulse_password@localhost:5432/tradepulse_db
```

### Практическая проверка готовности контура

Перед тем как приступить к установке библиотек `asyncpg` и `SQLAlchemy 2.0`, выполним комплексную проверку репозитория.

#### 1. Старт фоновой СУБД
Поднимем только контейнер базы данных через compose-профиль:

```bash
docker compose --profile dev up postgres -d
```

Проверим статус здоровья и доступность порта:

```bash
docker compose ps postgres
```

В выводе терминала контейнер `tradepulse-postgres` должен находиться в статусе `Up` с проброшенным портом `0.0.0.0:5432->5432/tcp`.

#### 2. Проверка Quality Gate
Убедимся, что кодовая база чиста от замечаний линтера и анализатора типов:

```bash
just check
```

Вывод:
```text
uv run ruff check .
All checks passed!
uv run mypy src
Success: no issues found in 7 source files
```

> **Грабли: Конфликт занятого порта 5432**  
> Если на вашей локальной машине уже установлена и запущена системная служба PostgreSQL (`brew services start postgresql` или `systemctl status postgresql`), Docker Compose не сможет привязать порт `5432` и вернет ошибку `Bind for 0.0.0.0:5432 failed: port is already allocated`.  
> 
> Для решения остановите локальную службу СУБД:
> ```bash
> # На macOS:
> brew services stop postgresql
> 
> # На Ubuntu / Debian:
> sudo systemctl stop postgresql
> ```
> После этого повторите запуск контейнера.
