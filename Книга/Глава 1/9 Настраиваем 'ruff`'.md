## 1.9. Автоматизация качества кода: настройка линтера и форматтера Ruff

### О чем эта подглава
В этой части мы настроим комплексную систему статического анализа и автоформатирования кодовой базы `TradePulse` на базе инструмента нового поколения `ruff`.

* **Что сделаем:** откажемся от разрозненных утилит (`flake8`, `black`, `isort`), внедрим быстрый Rust-линтер и форматтер `ruff`, сконфигурируем набор правил в `pyproject.toml`, разберем первые реальные ошибки линтера в файле `main.py` и устраним их как вручную, так и в автоматическом режиме.
* **Исходное состояние проекта:** в проекте инициализирована структура пакетов `src-layout`, настроены `Dockerfile` и профили `docker-compose.yml` (по итогам подглавы 1.8).
* **Ветка в репозитории:** `chapter-01-ruff-setup` (готовый результат для тех, кто читает главу изолированно).

### Проблема фрагментации инструментов контроля качества

Исторически проверка качества кода в Python-проектах требовала развертывания цепочки независимых инструментов:
* `black` — бескомпромиссное форматирование структуры строк и отступов;
* `isort` — сортировка и группировка импортов;
* `flake8` — базовый статический анализ стилистики и синтаксических ошибок;
* Сторонние плагины (`flake8-bugbear`, `flake8-comprehensions`) для выявления скрытых антипаттернов.

Каждая из этих утилит написана на Python, использует собственный парсер и требует отдельного конфигурационного файла. В крупных проектах такой стек создает задержки при запуске pre-commit хуков и в CI-пайплайнах, а также приводит к конфликтам форматирования между `black` и правилами длины строк `flake8`.

Инструмент **`ruff`** от компании Astral объединил все эти функции в одном бинарном файле на Rust. Работая в 10–100 раз быстрее аналогов, он полностью заменяет форматирование `black`, сортировку импортов `isort` и сотни правил плагинов `flake8` без конфликтов конфигурации.

### Шаг 1. Добавление зависимости

Инструменты форматирования и статического анализа нужны только на этапе разработки и тестирования, поэтому `ruff` добавляется в группу `dev`:

```bash
uv add --dev ruff
```

Пакетный менеджер зафиксирует утилиту в секции `[dependency-groups]` файла `pyproject.toml` и обновит контрольные суммы в `uv.lock`.

### Шаг 2. Конфигурация Ruff в pyproject.toml

Все правила объявляются централизованно в корневом манифесте `pyproject.toml`.

Откройте `pyproject.toml` и добавьте секции конфигурации линтера и форматтера:

```toml
[tool.ruff]
# Целевая версия интерпретатора для оптимизации синтаксических конструкций
target-version = "py313"

# Максимальная длина строки (стандартный компромисс между 79 по PEP 8 и 120)
line-length = 88

# Директории, исключаемые из проверок
exclude = [
    ".git",
    ".venv",
    "__pycache__",
    "build",
    "dist",
]

[tool.ruff.lint]
# Базовый набор наборов правил:
# E / W  - Pyflakes / pycodestyle (ошибки синтаксиса и стиля)
# F      - Pyflakes (неиспользуемые переменные, ошибки импортов)
# I      - isort (автоматическая сортировка импортов)
# B      - flake8-bugbear (типичные ошибки и логические ловушки)
# C4     - flake8-comprehensions (оптимизация списковых включений)
# UP     - pyupgrade (актуализация синтаксиса под Python 3.13)
# SIM    - flake8-simplify (упрощение громоздких ветвлений и логики)
# T20    - flake8-print (запрет отладочных вызовов print в продакшене)
select = [
    "E",
    "W",
    "F",
    "I",
    "B",
    "C4",
    "UP",
    "SIM",
    "T20",
]

# Исключения из правил (при необходимости)
ignore = [
    "E501",  # Перенос длинных строк передается на откуп ruff format
]

[tool.ruff.lint.isort]
# Группировка собственного пакета в отдельный блок импортов
known-first-party = ["tradepulse"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
line-ending = "auto"
```

### Шаг 4. Разбор природы ошибок: почему линтер ругается

Прежде чем нажимать автоисправление, важно понимать инженерную причину каждого предупреждения:

1. **`I001: Import block is un-sorted or un-formatted` (правило `isort`)**  
   * **Суть проблемы:** Импорты в модуле сбиты в кучу. В строке 4 сторонний фреймворк `fastapi` и внутренний модуль `tradepulse.core.logger` идут подряд без пустой строки-разделителя.
   * **Стандарт PEP 8:** Импорты всегда должны группироваться в три независимых блока, разделенных одной пустой строкой:
     1. Стандартная библиотека Python (`contextlib`, `typing`);
     2. Сторонние установленные библиотеки (`fastapi`);
     3. Локальные модули нашего проекта (`tradepulse`).

2. **`UP035: Import from collections.abc instead: AsyncIterator` (правило `pyupgrade`)**  
   * **Суть проблемы:** Мы импортировали абстрактный тип `AsyncIterator` из устаревшего для этих целей модуля `typing`.
   * **Стандарт Python 3.9+ (PEP 585):** Коллекции и абстрактные классы итераторов перенесены в модуль `collections.abc`. В современных версиях Python использование `typing.AsyncIterator` признано устаревшим (*deprecated*), и `ruff` (благодаря правилу `UP`) требует использовать современное пространство имен `collections.abc.AsyncIterator`.

### Шаг 5. Практика устранения замечаний

Устранить эти замечания можно двумя способами: вручную (чтобы закрепить понимание структуры кода) или с помощью автоматического исправления.

#### Вариант А: Ручное исправление в редакторе
Откройте файл `src/tradepulse/main.py` и приведите блок импортов к чистому виду:

```python
# 1. Стандартная библиотека
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

# 2. Сторонние зависимости
from fastapi import FastAPI

# 3. Локальные модули проекта (First-party)
from tradepulse.core.logger import logger, setup_logging
```

#### Вариант Б: Автоматическое исправление через Ruff
Обратите внимание на пометку в отчете: `[*] 2 fixable with --fix`. Знак `[*]` указывает, что `ruff` знает точный рецепт решения обеих проблем.

Выполните команду автоисправления:

```bash
uv run ruff check --fix .
```

`Ruff` самостоятельно:
* Заменит `typing.AsyncIterator` на `collections.abc.AsyncIterator`;
* Отсортирует строки по алфавиту внутри каждого блока;
* Вставит пустую строку перед импортом `tradepulse.core.logger`.

Проверим статус повторным запуском:

```bash
uv run ruff check .
```

Вывод:
```text
All checks passed!
```

### Шаг 6. Автоформатирование кодовой базы

Помимо проверки логики импортов и синтаксиса, необходимо выровнять пробелы, кавычки и переносы строк по единому стандарту оформления.

Выполните форматирование всего проекта:

```bash
uv run ruff format .
```

Если вы хотите запустить проверку без изменения файлов (например, в пайплайне CI/CD на GitHub Actions или GitLab CI), используйте флаг `--check`:

```bash
uv run ruff format --check .
```

> **Грабли: Конфликты локальных импортов**  
> Если `ruff` ставит ваши модули `from tradepulse...` в один блок со сторонними библиотеками вроде `fastapi`, убедитесь, что в `pyproject.toml` заполнена директива:
> ```toml
> [tool.ruff.lint.isort]
> known-first-party = ["tradepulse"]
> ```
> Без этой настройки линтер не сможет отличить установленный сторонний пакет от локального пакета в директории `src/`.
