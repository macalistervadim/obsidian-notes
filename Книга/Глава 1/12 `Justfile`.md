
## 1.12. Автоматизация задач разработки: декларативный интерфейс Justfile

### О чем эта подглава
В этой части мы избавимся от необходимости держать в памяти длинные терминальные команды с флагами и объединим управление жизненным циклом проекта в едином диспетчере команд `just`.

* **Что сделаем:** разберем ограничения классического `Makefile` в контексте современных Python-проектов, установим утилиту `just`, сформируем файл `Justfile` со всеми сценариями (запуск dev-сервера, линтинг, типизация, управление docker-профилями, открытие туннелей) и создадим единую точку входа для локальной разработки и CI/CD.
* **Исходное состояние проекта:** в проекте настроены `uv`, `docker-compose.yml`, `ruff`, `mypy` и туннель `tuna` (по итогам подглав 1.8–1.11).
* **Ветка в репозитории:** `chapter-01-justfile` (готовый результат для тех, кто читает главу изолированно).

> **Что почитать для углубления:**

> * Тим Питерс, *«Программирование бэкенда на Python. Практическое руководство»* (БХВ, 2025) — раздел об автоматизации контуров разработки и воспроизводимости сред.

### Проблема «забытых флагов» и почему Make устарел

К концу настройки первой главы в проекте `TradePulse` накопился внушительный набор команд:
* `uv run uvicorn tradepulse.main:app --app-dir src --reload`
* `uv run ruff check --fix . && uv run ruff format .`
* `uv run mypy src`
* `docker compose --profile dev up -d`
* `tuna http 8000`

Полагаться на то, что каждый разработчик в команде точно помнит все аргументы или ищет их по истории `bash_history`, нельзя. Исторически эту проблему решали с помощью утилиты `make` и файла `Makefile`. Однако `make` создавался в 1970-х годах для сборки бинарных файлов на языке Си на основе времени изменения файлов (*file-based build tool*):
1. **Специфика табов:** `make` требует строгой табуляции в синтаксисе. Обычный пробел ломает исполнение рецепта.
2. **Флаги `.PHONY`:** Чтобы `make` не искал файл с именем команды на диске (например, файл с именем `test` или `clean`), каждую нефайловую цель приходится объявлять через костыль `.PHONY: test clean`.
3. **Проблемы с Windows:** `Makefile` плохо портируется на машины под управлением Windows без дополнительных эмуляторов bash.

Инструмент **`just`** — это современная, написанная на Rust утилита для сохранения и выполнения команд проекта (*command runner*). Она берет лучший синтаксис от `make`, избавляется от концепции артефактов компиляции, нативно поддерживает загрузку переменных из `.env`, позиционные аргументы и справку по командам.

### Шаг 1. Установка утилиты just

Инструмент `just` распространяется в виде единого бинарного файла и ставится стандартными пакетными менеджерами:

```bash
# macOS (через Homebrew)
brew install just

# Linux (Debian / Ubuntu через apt или готовый бинарник)
cargo install just
# или через официальный установочный скрипт:
curl --proto '=https' --tlsv1.2 -sSf [https://just.systems/install.sh](https://just.systems/install.sh) | bash -s -- --to /usr/local/bin

# Windows (через Winget / Scoop)
winget install Casey.Just
```

Проверьте корректность установки:

```bash
just --version
```

### Шаг 2. Создание и структура Justfile

Создайте файл `Justfile` (без расширения, с заглавной или строчной буквы) в корне проекта `tradepulse`:

```bash
touch Justfile
```

Откройте `Justfile` в редакторе и опишите рецепты автоматизации нашего проекта:

```just
# Загрузка переменных окружения из .env по умолчанию
set dotenv-load := true

# По умолчанию при вызове `just` без аргументов выводим список доступных команд
default:
    @just --list

# ==============================================================================
# 1. Запуск и локальная разработка
# ==============================================================================

# Запуск локального сервера разработки с горячей перезагрузкой
run:
    uv run uvicorn tradepulse.main:app --app-dir src --reload --host 0.0.0.0 --port 8000

# Открытие защищенного публичного туннеля через tuna
tunnel port="8000":
    tuna http {{port}}

# ==============================================================================
# 2. Контроль качества кода (Quality Gate)
# ==============================================================================

# Комплексная проверка: сортировка импортов, линтинг и строгая типизация
check: lint typecheck

# Быстрая проверка линтером Ruff
lint:
    uv run ruff check .

# Автоматическое исправление ошибок линтера и форматирование кода
fix:
    uv run ruff check --fix .
    uv run ruff format .

# Строгая статическая верификация типов через Mypy
typecheck:
    uv run mypy src

# ==============================================================================
# 3. Управление контейнерами Docker Compose
# ==============================================================================

# Запуск окружения разработки (api-dev + mailpit)
dev-up:
    docker compose --profile dev up -d

# Остановка всех запущенных сервисов Compose
dev-down:
    docker compose down

# Просмотр логов контейнеров в реальном времени
logs:
    docker compose logs -f

# Пересборка боевого образа приложения без кэша
build-prod:
    docker build --no-cache -t tradepulse-api:latest .

# ==============================================================================
# 4. Обслуживание зависимостей и окружения
# ==============================================================================

# Полная синхронизация виртуального окружения по lock-файлу
sync:
    uv sync

# Очистка временных файлов кэша Python и сборщиков
clean:
    rm -rf .pytest_cache .ruff_cache .mypy_cache build dist htmlcov
    find . -type d -name "__pycache__" -exec rm -rf {} +
```

### Шаг 3. Практическая работа с командами

#### 1. Интерактивная справка по проекту
Главное удобство `just` — самодокументируемость. Новый разработчик, только что склонировавший репозиторий `TradePulse`, вводит:

```bash
just
```

И видит аккуратный список всех доступных в проекте процедур с комментариями:

```text
Available recipes:
    build-prod # Пересборка боевого образа приложения без кэша
    check      # Комплексная проверка: сортировка импортов, линтинг и строгая типизация
    clean      # Очистка временных файлов кэша Python и сборщиков
    default    # По умолчанию при вызове `just` без аргументов выводим список доступных команд
    dev-down   # Остановка всех запущенных сервисов Compose
    dev-up     # Запуск окружения разработки (api-dev + mailpit)
    fix        # Автоматическое исправление ошибок линтера и форматирование кода
    lint       # Быстрая проверка линтером Ruff
    logs       # Просмотр логов контейнеров в реальном времени
    run        # Запуск локального сервера разработки с горячей перезагрузкой
    sync       # Полная синхронизация виртуального окружения по lock-файлу
    tunnel     # Открытие защищенного публичного туннеля через tuna
    typecheck  # Строгая статическая верификация типов через Mypy
```

#### 2. Запуск цепочки проверок качества
Перед коммитом достаточно выполнить одну короткую команду:

```bash
just check
```

`just` последовательно запустит рецепт `lint` (`ruff check .`), а затем `typecheck` (`mypy src`). Если на каком-то шаге произойдет ошибка, выполнение мгновенно остановится с понятным кодом возврата.

#### 3. Передача аргументов в рецепты
Обратите внимание на рецепт туннеля: `tunnel port="8000":`.  
Если вызвать команду без аргументов:
```bash
just tunnel
```
туннель откроется на стандартный порт `8000`. Если же сервер был запущен, например, на порту `8080`, порт передается позиционно:
```bash
just tunnel 8080
```

> **Грабли: Подавление вывода команд символом `@`**  
> По умолчанию `just` перед исполнением строки печатает саму команду в терминал. Если вы хотите скрыть служебный вывод и оставить только результат работы утилиты (как сделано в рецепте `default: @just --list`), добавьте префикс `@` в начале строки рецепта.

### Контрольная точка
К этому моменту все разрозненные инженерные инструменты первой главы объединены в единую декларативную систему:
1. Установлен инструмент автоматизации `just`.
2. Создан `Justfile`, инкапсулирующий сложные флаги запуска Uvicorn, Ruff, Mypy, Docker Compose и Tuna.
3. Проект стандартизирован: для старта работы любому инженеру достаточно выполнить `just sync` и `just run`.
