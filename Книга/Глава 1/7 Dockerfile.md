## 1.7. Контейнеризация FastAPI: многоэтапная сборка с uv и Docker

### О чем эта подглава
В этой части мы упакуем сервис `tradepulse` в промышленный Docker-образ, оптимизированный по размеру, скорости пересборки и требованиям безопасности.

* **Что сделаем:** создадим файл исключений `.dockerignore`, напишем production-ready `Dockerfile` с использованием пакетного менеджера `uv`, кэшированием слоев BuildKit и запуском от непривилегированного пользователя, а также соберем и протестируем контейнер.
* **Исходное состояние проекта:** в репозитории инициализирована кодовая база `tradepulse` с зависимостями в `pyproject.toml` и зафиксированным lock-файлом `uv.lock` (по итогам подглавы 1.6).
* **Ветка в репозитории:** `chapter-01-dockerfile` (готовый результат для тех, кто читает главу изолированно).

### Зачем контейнеризация FastAPI-сервису

В промышленной разработке ключевая проблема развертывания — синдром «на моей машине все работает». Различия в версиях системных библиотек, компиляторов C (необходимых для сборки быстрых драйверов вроде `asyncpg`) и архитектурах ОС приводят к сбоям на сервере.

Docker решает эту задачу, фиксируя:
1. **Изоляцию среды:** точный дистрибутив Linux и срез версии Python независимо от ОС хоста.
2. **Системные зависимости:** изоляцию бинарных библиотек (`libpq-dev`, `gcc`) без загрязнения операционной системы разработчика.
3. **Единый артефакт доставки:** один и тот же образ проходит локальную отладку, прогон тестов в CI/CD и запуск в Kubernetes.

Для контейнеризации приложения создаются два конфигурационных файла в корне проекта: `.dockerignore` и `Dockerfile`.

---

### Шаг 1. Формирование .dockerignore

Перед описанием инструкций сборки необходимо исключить попадание лишних файлов хоста в контекст сборки Docker. Это уменьшает размер контекста, ускоряет отправку файлов в демон сборщика и предотвращает затирание зависимостей внутри контейнера локальным виртуальным окружением.

Создайте файл `.dockerignore` в корне проекта `tradepulse`:

```text
__pycache__
*.pyc
*.pyo
*.pyd
.Python
env/
venv/
.venv/
.env
.git
.gitignore
.dockerignore
.pytest_cache/
.coverage
htmlcov/
```

> **Важно:** Исключение `.env` и локальной папки `.venv` строго обязательно. Переменные окружения должны передаваться в контейнер в рантайме (при запуске), а локальное виртуальное окружение хоста несовместимо с бинарным окружением Linux внутри образа.

---

### Шаг 2. Оптимальный Dockerfile для FastAPI и uv

В качестве базы используется официальный образ `python:3.13-slim`. Он содержит минимальный дистрибутив Debian, обеспечивая компактный итоговый размер (около 150–200 МБ) и сниженную площадь уязвимостей по сравнению со стандартными образами Python.

Создайте файл `Dockerfile` в корне проекта:

```dockerfile
# 1. Базовый образ
FROM python:3.13-slim

# 2. Копирование скомпилированного бинарника uv из официального образа Astral
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

# 3. Настройка параметров окружения Python и uv
# UV_COMPILE_BYTECODE: компилирует .py в байт-код при установке (ускоряет холодный старт FastAPI)
# UV_LINK_MODE=copy: заставляет uv копировать файлы вместо жестких ссылок (важно для файловых систем контейнеров)
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy \
    APP_HOME=/app

WORKDIR $APP_HOME

# 4. Установка сторонних зависимостей с кэшированием слоев
# Копируем манифесты отдельно, чтобы не сбрасывать кэш пакетов при изменении бизнес-логики
COPY pyproject.toml uv.lock ./

# Устанавливаем только продакшен-зависимости (без pytest, ruff и dev-инструментов)
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev --no-install-project

# 5. Создание непривилегированного пользователя в целях безопасности
RUN useradd -m -u 1000 appuser && \
    chown -R appuser:appuser $APP_HOME

# 6. Копирование исходного кода сервиса и финальная установка
COPY ./src ./src
COPY README.md ./

# Регистрируем сам проект в окружении (синхронизация метаданных и консольных скриптов)
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev

# Добавляем созданное окружение uv в переменную PATH
ENV PATH="$APP_HOME/.venv/bin:$PATH"

# 7. Права доступа и команда запуска
USER appuser
EXPOSE 8000

# Запуск ASGI-сервера Uvicorn
CMD ["uvicorn", "tradepulse.main:app", "--app-dir", "src", "--host", "0.0.0.0", "--port", "8000"]
```

---

### Архитектурные особенности сборки

1. **Многоэтапное копирование бинарника (`COPY --from=...`):**  
   Использование готового бинарника `uv` исключает необходимость устанавливать дополнительные пакетные менеджеры через `pip` или компилировать исходники, экономя время сборки.
2. **Двухэтапная синхронизация (`uv sync`):**  
   * Сначала выполняется `uv sync --frozen --no-dev --no-install-project`. Устанавливаются только внешние библиотеки из `uv.lock`. Если изменился код в директории `src/`, этот слой полностью берется из кэша Docker.
   * Второй вызов монтирует исходный код проекта. Пересборка логики занимает доли секунды.
3. **Кэш BuildKit (`--mount=type=cache`):**  
   Инструкция кеширует загруженные wheel-пакеты между сборками на рабочей машине, исключая повторное скачивание зависимостей из сети.
4. **Запуск без root-прав (`USER appuser`):**  
   Запуск веб-приложений под пользователем `root` в контейнерах — серьезная брешь в безопасности. Создание пользователя `appuser` с фиксированным UID `1000` ограничивает доступ процесса к ресурсам хоста при возможной компрометации приложения.

### Практическая работа: сборка и запуск

#### 1. Сборка образа
Запустите сборку с указанием тега в терминале из корня проекта:

```bash
docker build -t tradepulse-api:latest .
```

#### 2. Фоновый запуск контейнера
Запустите созданный образ с пробросом сетевого порта:

```bash
docker run -d \
  --name tradepulse-api \
  -p 8000:8000 \
  tradepulse-api:latest
```

* Флаг `-d` (detached) запускает контейнер в фоновом режиме.
* Флаг `-p 8000:8000` мапит входящий порт хоста `8000` на порт `8000` внутри изолированного контейнера.

> **Грабли: Проверка логов при падении контейнера**  
> Если контейнер завершил работу сразу после запуска (статус `Exited`), проверьте вывод логов Uvicorn:
> ```bash
> docker logs tradepulse-api
> ```
> Частая причина — опечатка в пути к приложению (`--app-dir src` относительно директории `WORKDIR /app`).

#### 3. Проверка работоспособности
Убедитесь, что сервис успешно отвечает, открыв интерактивную документацию Swagger UI в браузере:  
`http://localhost:8000/docs`

Для остановки и удаления тестового контейнера выполните:
```bash
docker stop tradepulse-api
docker rm tradepulse-api
```
